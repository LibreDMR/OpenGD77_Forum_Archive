Retrofit GPS to a MD9600

  • Quote

Post by VK3KYY » Sat Oct 12, 2024 4:55 am

I thought I'd share some results of fitting a GPS module into a new MD9600 and and into an old MD9600

Both the radios didn't come with a GPS fitted.

I bought some ATGM336H modules from AliExpress, which are a separate receiver PCB and small rectangular antenna.
Like this module. https://www.aliexpress.com/item/4001147538089.html
Screenshot 2024-10-12 at 15-20-49 GPS BDS dual-mode module flight control satellite positioning navigator ATGM336H replacement for arduino NEO-M8N NEO-6M - AliExpress.png (105.62 KiB) Viewed 5849 times
The inside of the front panel of the MD9600 has some plastic lugs which are probably where the factor fitted GPS antenna is fitted, and the antennas with this sort of module fit inbetween these lug.

There seems to be some slight different in the placement of the lugs between the older e.g. V2 hardware radio and the V5 radios, so that some trimming may be needed on the lugs in the V2 radio so that the antenna will fit.

The antenna can then be glued in place.

The GPS module can easily be glued to the back of the PCB in the front panel of the radio, and connected to the pads on the PCB where the factory GPS module would be fitted.

This arrangement worked well on my V5 hardware radio, and I was able to receive up to 20 satellites even indoors.


However....

When I tried to fit the same module into my V2 hardware radio, it had great difficulty receiving more than 1 or 2 satellites.

Initially I thought I had a faulty antenna or faulty, GPS module, so I removed both and fitted another identical brand new module and brand new antenna, but the problem still persisted.

After a lot of experimentation, I found that if I power the GPS module from a separate supply that it worked OK, but not when I powered it from the radio.

I thought the problem may be a poor earth / negative connection to the display or poor supply voltage connection, as both go via a thin ribbon cable, however even using an additional earth wire etc didn't make any difference.


The problem was actually that the supply voltage to the GPS is very noisy on my V2 hardware radio.

I noticed on the schematic that the supply line is heavilty decoupled with multiple capacitors, but as far as I am aware, my V2 radio has all these decompiling capacitors and the only items not fitted are the GPS module and the antenna.

Just adding some decompiling didn't fix the problem, so finally I have built a L/C low pass filter consisting of a 1mH inductor and a 10uF Tant bead capacitor. These values probably aren't critical. I just happend these components in my box of spares, so I used what I had

But the V2 radio definitely needed the supply rail to be cleaned.

Possibly its only this type of module which can't handle a noisy supply rail, but other modules also have the same problem

I tried some GP-02 branded modules, but they had the same problem, and checking the NMEA data, I saw that both the GP-02 module and ATGM336H module both use the same GPS chip



I also noticed that this geration of GPS modules, only support American GPS, Chinese Beidou and also Japanese QNSS satellites. They don't support European Galileo or Russian GLONASS satellites or others like SBAS.

So as a matter of interest I have now ordered some M10 generation GPS modules, which should support all GPS satellite systems.
However I can't find any modules which have a small enough antenna, to make them very suitable to fit in the MD9600.

I have also ordered some bare modules, with no PCB, https://www.aliexpress.com/item/1005007789129084.html in the hope that I can solder an antenna connection, however I don't know how practical this will be .

These new modules also default to higher baud rates which is not currently compatible with the OpenGD77 firmware, so I will have to reconfigure them before use or possibly modify the OpenGD77 firmware to detect the baud rate.

Doing some further experiments, I ordered some u-blox M10 clone GPS modules from AliExpress hoping they would work better than the cheap ATGM336H module, becasue M10 class GPS can receive the 4 major GPS constellations, not just American and Chinese

However the data output from these is not currently compatible with the OpenGD77 firmware for a number of reasons.

1. These M10 class modules don't default to 9600, they often default to 38400
2. Some of NMEA sequences sent by u-blox M10 class devices seem to deviate from the normal NMEA standard and are not processed correctly by the firmware

Firsly.
Setting the module to 9600 baud before connecting to the MD9600 would partially solve the first problem, however the reason these modules default to 38400 baud is because they send much more data than modules which only handle 1 or 2 satellite constellations, and because they send all the data once per second, its likely it could not all be sent in one second

So. I am writing support to detect if the GPS module uses a higher baud rate.

Secondly. T
o support the u-blox and also some other module types e.g Trimble. It will probably be necessary to modify the parsing of the GSV NMEA data messages. But because u-blox and Trimble and other other manufacturers do not seem to agree on the GSV messages, this may be difficult.


Overall, I am not actually seeing much benefit from using these M10 class modules, but so far I only tested 2 types, Quescan and EByte, and the EByte device I have is only the bare chip module not a whole PCB, so at the moment I don't have a backup battery for it, so I can't test the Hot Start

https://www.aliexpress.com/item/1005005403914270.html

https://www.aliexpress.com/item/1005007789129084.html

I made the mistake of not ordering the EByte device as a module on a PCB with an antenna, and it has been problematic to solder to this tiny device.
The reason I bought just the device not a module, is becasue I had the idea to fit it inside my UV380 or MD2017 instead of the official GPS, however it seems that these M10 class devices may need a larger antenna, becuase using a small antenna (10mm x 25mm) from a ATGM336H module, didn't work well, and the EByte module didn't receive many satellites.





So I've now ordered the same Ebyte device as a module with a separate antenna

https://www.aliexpress.com/item/1005007740983988.html

and also a "Beitian" brand GPS module on a PCB with backup battery and antenna etc

https://www.aliexpress.com/item/1005005209505077.html




BTW.

I found this PC program from the manufacturer of the ATGM336H module, called GnssToolKit3
https://github.com/zxcwhale/GnssToolKit ... s/releases

Which has a quite good display fo the satellite information.

Following on from my experiments retro-fitting a GPS module inside my MD9600, I've now done an enhancement, by fitting a 3.5mm hack socket on the left side of the front panel.

I can then connect and external GPS puc by plugging it in.

The stereo jack socket I used is a PCB mount version, because it has 5 pins, and allows the internal GPS power and data to be disconnected when the external GPS is plugged in.

Warning.
I do not connect or disconnect the external GPS while the radio is turned on, as jack plugs can short their pins together while being plugged in or unplugged
