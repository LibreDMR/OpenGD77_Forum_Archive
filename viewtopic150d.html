Without seeing all the code, its difficult to know exactly what you did

However it looks like you added another block of code like this


Code: Select all

	GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT;
	GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
	GPIO_InitStruct.Pull = GPIO_PULLDOWN;

	GPIO_InitStruct.Pin = LCD_D0_Pin | LCD_D1_Pin | LCD_D2_Pin | LCD_D3_Pin;
	HAL_GPIO_Init(GPIOD, &GPIO_InitStruct);

	GPIO_InitStruct.Pin = LCD_D4_Pin | LCD_D5_Pin | LCD_D6_Pin | LCD_D7_Pin;
	HAL_GPIO_Init(GPIOE, &GPIO_InitStruct);
Which sets the 'input' pins to output, and effectly kept the previous code that sets the pins to input.

This probably has the effect of driving the pins low, but you should probably also have also added

Code: Select all

		HAL_GPIO_WritePin((GPIOD, LCD_D0_Pin | LCD_D1_Pin | LCD_D2_Pin | LCD_D3_Pin, GPIO_PIN_RESET);

		HAL_GPIO_WritePin((GPIOE, LCD_D4_Pin | LCD_D5_Pin | LCD_D6_Pin | LCD_D7_Pin, GPIO_PIN_RESET);

before the call to HAL_GPIO_Init()

If ypu look in main.c (which is automatically generated code from the STM32 Cube IDE), you will see that it had multiple calls to HAL_GPIO_WritePin() before calling Init

e.g.


Code: Select all

  HAL_GPIO_WritePin(GPIOE, DMR_SPI_CS_Pin|C6000_PWD_Pin, GPIO_PIN_SET);


The keyboard input pins are shared with the display output pins, and the same pins are written to by the FSMC controller part of the MCU during display updates

I checked the code and we do set the FSMC output register to 0 in the renderRows() function

Code: Select all

	*((volatile uint8_t*) LCD_FSMC_ADDR_DATA) = 0;// write 0 to the display pins , to pull them all low, so keyboard reads don't need to

So this should have left the pins driven low, and it should not have been necessary to set the GPIO pins to Output before setting them to input


However, its possible that the MCU has some "Errata" aka bugs in its silicon.


Can you look in the Firmware Info screen, and check whether your radio has a genuine STM MCU or whether it has a Chinese clone.

If the CPU type is "STM" its genuine, if it reads "TYT" then its the unknown Chinese clone , fitted by TYT and probably also the same clone used in the Baofeng radio.

OK

Looks like when the pin functionality is changed from FSMC to GPIO, that there is probably a glitch , which may randomly drive the pins high for a short time before.

Hence your code of setting them to Output probably drives them low.

However, I think for safety, that the GPIO pins should be set to Low i.e "GPIO_PIN_RESET".

by adding these 2 lines to your code, if you didn't already do that

Code: Select all

		HAL_GPIO_WritePin((GPIOD, LCD_D0_Pin | LCD_D1_Pin | LCD_D2_Pin | LCD_D3_Pin, GPIO_PIN_RESET);
		HAL_GPIO_WritePin((GPIOE, LCD_D4_Pin | LCD_D5_Pin | LCD_D6_Pin | LCD_D7_Pin, GPIO_PIN_RESET);
Also, the time the pins are being driven low will be quite short, and I would also be tempted to add a small for(;;) loop delay between driving the pins low and setting then to input


Setting the pins low is probably the most important and the delay would be optional.

Could you please try adding my code, and confirm there are no adverse effects.
