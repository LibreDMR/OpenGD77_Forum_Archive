The data you posted does not make sense

Why would 0's be 100% correct, and the Silence frame also be OK, but sending all 1's have very high BER

How are you handling the FEC encoding and decoding of your data ?


It should also be noted that although you are implying this is a bug on all radios, except perhaps the MD9600, that AFIK Colin did not find any errors with the GD77 which already used the correct AF gain setting.

Its only the UV380/DM1701 where we know the AF gain setting was too high and resulted in audio levels > 1V PP which are greater than the maximum input for the C6000. The new setting for the UV380/DM1701 now sends 0.8V PP to the C6000 which is the optimial level on that radio

Also. Daniel tried changing the MD2017 AF gain to the same setting that is required for the UV380/DM1701 but this resulted in problems on that radio.
So probably because the MD2017 has some MUX between the dual AT1846S and the C6000 that there is some attenuation in AF signal level on the MD2017 and the maximum AF gain, or something close to maximum AF gain is required in the MD2017

At the moment we will only be changing the AF gain setting in the UV380/DM1701 code.

It was too high risk to include in the Stable release, as reducing the AF gain may cause problems for people using repeaters with inaccurate Tx deviation settings.

Hence we will release a new Beta or possibly an Experimental version with this change , this weekend

The change will only be to the UV380/DM1701 code, because this is the only radio where the problem is actually known to exist.
The GD77 type radios already use a lower AF gain setting, and the MD2017 hardware is different and seems to require a very high gain setting
